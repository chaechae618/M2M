최종 결론

오늘 실험 기준 최고 성능 방식은 general-direct LLM gate다. 단순 threshold 재설정보다 별도 general-direct 판단 경로를 두는 방식이 llm_direct 케이스를 가장 많이 회수하면서도 wrong_direct를 만들지 않았다.

주요 관찰

1. Baseline 문제

Baseline은 mentor_needed로 과도하게 보내는 경향이 강했다. 전체 185건 중 140건을 멘토 연결로 예측했고, llm_direct recall은 0.1556에 머물렀다.

  • llm_direct 45건 중 34건이 mentor_needed로 밀림
  • partial 129건 중 98건도 mentor_needed로 밀림
  • 안전성은 좋지만 자동 응답 가능 케이스를 너무 많이 놓침

2. Usable fallback 효과

search-first에서 검색 결과가 있는데 verifier가 usable을 비우는 경우, 일반 정보성 질문에 한해 conservative partial로 복구했다.

  • 19건 복구
  • Accuracy 0.2486 → 0.2757
  • wrong_direct 0 유지
  • 다만 llm_direct recall 개선은 없음

3. General-direct gate가 강했던 이유

많은 llm_direct 케이스는 기존 멘토 답변 corpus에 근거가 없거나 낮은 similarity를 보인다. 따라서 retrieval threshold를 낮추는 것보다, 일반 커리어 지식으로 직접 답변 가능한 질문인지 별도 판정하는 것이 더 맞다.

  • LLM gate 후보 33건 중 32건 허용
  • 거절 케이스: direct_supp_011
  • wrong_direct 없이 direct recall 0.8667 확보

4. CONFLARE 적용 결과

논문 아이디어는 retrieval calibration framework로는 유용하지만, 현재 Agent2에 threshold replacement로 직접 적용하는 것은 맞지 않았다.

  • source-score conformal은 threshold가 너무 높아 검색 붕괴 발생
  • runtime conformal은 score mismatch를 줄였지만 wrong_direct 5건 발생
  • llm_direct 문제는 retrieval calibration만으로 해결되지 않음

다음 작업

  1. general_direct verdict 또는 answer mode 추가
    현재 직접 답변은 retrieved mentor answer 기반에 가깝다. no-similar 케이스에도 대응하려면 일반 지식 답변 모드를 분리해야 한다.
  2. LLM gate production prompt 추가
    질문이 일반 커리어 지식으로 안전하게 답변 가능한지, 개인 판단·자료 검토·고위험 조언이 필요한지 구분한다.
  3. general-direct 전용 verifier 추가
    기존 verifier는 retrieved answer faithfulness에 묶여 있으므로, 일반 답변의 안전성·범위·비개인화 여부를 따로 검증해야 한다.
  4. 회귀 평가 자동화
    이번 validation set 185건을 고정 regression suite로 두고, wrong_direct, direct recall, partial recall을 계속 추적한다.
  5. API key 교체
    실험 중 사용한 OpenAI key는 대화에 노출되었으므로 폐기하고 새 key로 교체한다.
